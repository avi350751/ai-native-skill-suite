# Diagnostic and Roadmap

Use this reference to turn a vague request such as “teach me AI” into a relevant, applied path.

## Minimum learner profile

Collect or infer:

- target role, course, project or first-job outcome;
- education and strongest prior capabilities;
- typical tasks and artifacts;
- comfort with documents, spreadsheets, search, data, code and automation;
- AI tools already tried and how outputs are checked;
- available hours per week, device/access constraints and preferred learning mode;
- workplace or school rules, data sensitivity and consequence of error.

Do not make the learner complete a long intake if a useful first plan can be offered from partial information. Mark assumptions and make the first week diagnostic.

## Capability diagnostic

Rate each dimension from 0 to 4 and attach one sentence of evidence.

| Dimension | 0–1 | 2 | 3 | 4 |
|---|---|---|---|---|
| AI mental model | magical or fearful view | knows common capabilities and limits | predicts likely failure modes | chooses fit-for-purpose approaches |
| Task decomposition | gives broad requests | separates major steps | defines inputs, outputs and criteria | redesigns work around dependencies and decisions |
| Context construction | supplies little context | adds role and examples | curates sources, constraints and formats | maintains reusable context with provenance |
| Verification | accepts fluent output | spot-checks obvious facts | uses source, calculation and peer checks | designs layered evaluation and escalation |
| Tool/data fluency | struggles with basic artifacts | works in common office tools | combines files, data and AI tools | automates safely across tools |
| Domain judgment | lacks fundamentals | applies taught rules | handles ambiguity with reasons | recognizes exceptions and trade-offs |
| Workflow thinking | one prompt, one answer | repeats a useful sequence | builds a checked feedback loop | improves the loop from operational evidence |
| Responsible use | unaware of exposure | follows stated rules | identifies privacy, bias and IP risks | designs proportionate safeguards |

The lowest score is not automatically the first priority. Prioritize dimensions that block the target outcome or create material risk.

## Roadmap architecture

Build the plan in four stages. Compress or expand them to match the learner's schedule.

### Stage A — Ground safely

Outcome: the learner can explain what generative AI does, identify common failure modes, handle data safely and write a bounded task brief.

Useful artifacts: capability/limitation note, safe-use checklist, annotated comparison of an unchecked and verified answer.

### Stage B — Assist real work

Outcome: the learner improves two or three authentic tasks without surrendering judgment.

Teach the context packet: goal, audience, source material, constraints, examples, output format and acceptance criteria. Include retrieval/search, drafting, analysis or practice only as relevant to the learner's work.

Useful artifacts: research brief, analysis workbook, draft-and-review log, code change with tests, lesson plan or other stream-specific output.

### Stage C — Redesign a workflow

Outcome: the learner maps a multi-step process and builds a repeatable loop.

The loop should make visible: goal → context → AI action → observation → evaluation → correction → next action. Add human approval where error cost, ambiguity or accountability requires it.

Useful artifacts: before/after process map, reusable templates, evaluation checklist, simple automation or operating guide.

### Stage D — Work AI-natively

Outcome: the learner chooses human and AI roles intentionally, monitors outcomes and improves the system.

Useful artifacts: capstone workflow, outcome comparison, failure analysis, limitations statement and improvement backlog.

## 30/60/90-day default

Use this only when the user asks for a time-based plan or gives no alternative.

- **Days 1–30:** foundation plus three small H1 tasks. Establish safe-use and verification habits.
- **Days 31–60:** deepen one field-relevant capability and redesign one recurring workflow at H2.
- **Days 61–90:** deliver a supervised capstone, measure results, document controls and teach the workflow to another person.

Each week should contain learn → observe → practice → verify → reflect. Limit conceptual study to what the next artifact requires.

## Opportunity selection

Prefer tasks that are frequent, reviewable, low-to-moderate risk, supported by accessible context and valuable enough to motivate practice. Avoid a first project whose failure could harm a person, violate policy, alter a production system or create an irreversible external commitment.

Rank candidate tasks on a simple 1–5 scale:

- value or learning leverage;
- frequency;
- ability to verify;
- context/data readiness;
- risk, reverse-scored;
- learner motivation.

Explain the top choices rather than hiding judgment behind a total score.

## Deliverable template

Produce a compact plan with:

1. learner and target profile;
2. capability baseline with evidence;
3. highest-leverage gaps;
4. staged plan and weekly cadence;
5. real artifacts and success criteria;
6. safety and verification controls;
7. measurement and review points.
